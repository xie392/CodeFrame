## 上下文

当前项目使用 Tailwind `darkMode: "class"` 策略 + CSS 变量双套定义实现亮/暗主题切换。设计稿仅定义暗色主题，亮色主题是手动推导的近似配色，存在视觉不匹配问题。

移除暗色主题后，CSS 从"双套变量 + 选择器覆盖"简化为"单套固定值"，代码更简洁、维护成本更低。

## 目标 / 非目标

- 目标：
  - 所有界面仅使用亮色主题，视觉一致
  - 简化 CSS 变量体系（单套、固定值）
  - 移除主题切换相关的所有代码
- 非目标：
  - 不重新设计亮色配色（沿用当前 `:root` 中的亮色值）
  - 不影响代码高亮主题（`CodeTheme`，独立于 UI 主题）

## 决策

### 决策 1：直接删除 vs 条件编译
- **选择**：直接删除暗色主题代码
- **原因**：Chrome 扩展无服务端条件，静态删除最简洁
- **替代方案**：保留暗色代码但禁用 → 增加死代码

### 决策 2：CSS 变量保留 vs 内联
- **选择**：保留 CSS 变量，但移除双套分支
- **原因**：shadcn/ui 组件仍依赖 `var(--xxx)` 格式，保留变量可维持兼容性
- **替代方案**：全部改为 Tailwind arbitrary values → 破坏 shadcn/ui 组件

### 决策 3：use-theme.ts 处理
- **选择**：删除整个文件
- **原因**：唯一调用方是 Popup 的主题切换按钮，按钮将一并移除
- **注意**：`chrome.storage.local` 中的 `codeframe-theme` 键无需主动清理

## 风险 / 权衡

- **已存暗色偏好的用户** → 重新打开后将自动回退到亮色，无迁移成本（仅视觉变化）
- **未来恢复暗色主题** → 需要重新实现，但 `useTheme` hook 逻辑简单，可快速重建
