## 新增需求

### 需求：项目目录结构

项目**必须**遵循模块化的目录结构，支持 Chrome 扩展的多页面架构。

#### 场景：源代码目录结构

- **当** 开发者查看项目结构
- **那么** `src/` 目录**必须**包含以下子目录：
  - `background/` - Service Worker 入口
  - `popup/` - 主弹窗页面
  - `editor/` - 图片编辑器页面
  - `codegen/` - 代码生成器页面
  - `content/` - 内容脚本
  - `shared/` - 共享模块
  - `options/` - 设置页面

#### 场景：公共资源目录结构

- **当** 开发者查看项目结构
- **那么** `public/` 目录**必须**包含以下子目录：
  - `icons/` - 扩展图标（16/48/128px）
  - `themes/` - 预设主题配置

#### 场景：共享模块结构

- **当** 开发者查看 `src/shared/` 目录
- **那么** 该目录**必须**包含以下模块：
  - `constants.ts` - 全局常量
  - `types.ts` - TypeScript 类型定义
  - `messages.ts` - 消息类型定义
  - `utils/` - 工具函数目录

### 需求：入口文件规范

每个页面模块**必须**有标准的入口文件结构。

#### 场景：页面模块入口

- **当** 开发者创建新的页面模块
- **那么** 该模块**必须**包含：
  - `index.html` - HTML 入口
  - `App.tsx` - React 组件入口
  - `main.tsx` - 应用入口
  - `components/` - 组件目录

#### 场景：Service Worker 入口

- **当** 开发者查看 background 模块
- **那么** 该模块**必须**包含 `index.ts` 作为 Service Worker 入口

#### 场景：内容脚本入口

- **当** 开发者查看 content 模块
- **那么** 该模块**必须**包含 `index.ts` 作为内容脚本入口
