## 新增需求

### 需求：Editor 模块化架构

Editor 必须采用模块化架构，将功能拆分为独立的组件、Hooks、服务和状态管理模块，确保代码可维护、可测试、可扩展。

#### 场景：主入口文件精简

- **当** 开发者查看 `src/editor/App.tsx`
- **那么** 文件行数必须小于 200 行
- **且** 文件只负责组件组合和协调
- **且** 不包含业务逻辑实现

#### 场景：组件独立文件

- **当** 开发者查看 `src/editor/components/` 目录
- **那么** 每个组件必须位于独立目录
- **且** 每个组件文件行数必须小于 300 行
- **且** 组件必须通过 index.tsx 导出

#### 场景：状态管理统一

- **当** 开发者需要访问或修改 Editor 状态
- **那么** 必须通过 Zustand Store 进行
- **且** 状态定义必须集中在 `src/editor/store/editor-store.ts`
- **且** 组件不得直接使用 useState 管理全局状态

#### 场景：服务层封装

- **当** 开发者需要 Canvas 渲染功能
- **那么** 必须通过 `src/editor/services/canvas-renderer.ts` 调用
- **当** 开发者需要图形创建功能
- **那么** 必须通过 `src/editor/services/shape-factory.ts` 调用
- **当** 开发者需要导出功能
- **那么** 必须通过 `src/editor/services/export-service.ts` 调用

#### 场景：自定义 Hooks 抽取

- **当** 开发者需要缩放平移功能
- **那么** 必须使用 `useZoomPan` Hook
- **当** 开发者需要图形操作功能
- **那么** 必须使用 `useShapeHandlers` Hook
- **当** 开发者需要导出功能
- **那么** 必须使用 `useExport` Hook

#### 场景：类型和常量管理

- **当** 开发者需要 Editor 相关类型
- **那么** 必须从 `src/editor/types.ts` 导入
- **当** 开发者需要 Editor 相关常量
- **那么** 必须从 `src/editor/constants.ts` 导入

### 需求：Editor 单元测试覆盖

Editor 核心模块必须有单元测试覆盖，确保重构后功能稳定。

#### 场景：Store 测试覆盖

- **当** 运行单元测试
- **那么** `editor-store.ts` 测试覆盖率必须 ≥ 80%

#### 场景：Hooks 测试覆盖

- **当** 运行单元测试
- **那么** 所有 Hooks 测试覆盖率必须 ≥ 60%

#### 场景：服务层测试覆盖

- **当** 运行单元测试
- **那么** 所有服务层测试覆盖率必须 ≥ 60%

### 需求：Editor 功能不变

重构后 Editor 所有用户可见的功能必须保持不变。

#### 场景：图形标注功能不变

- **当** 用户使用重构后的 Editor
- **那么** 箭头、矩形、文字、马赛克标注功能必须正常工作
- **且** 绘制、选择、拖拽、调整大小操作必须正常

#### 场景：导出功能不变

- **当** 用户使用重构后的 Editor
- **那么** PNG 导出功能必须正常工作
- **且** 复制到剪贴板功能必须正常工作
- **且** 导出质量必须与重构前一致

#### 场景：历史记录功能不变

- **当** 用户使用重构后的 Editor
- **那么** 撤销/重做功能必须正常工作
- **且** 操作历史持久化必须正常工作

#### 场景：设置功能不变

- **当** 用户使用重构后的 Editor
- **那么** 所有属性面板设置必须正常工作
- **且** 帧设置、水印设置必须正常工作
