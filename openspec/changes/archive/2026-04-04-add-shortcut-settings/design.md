## 上下文

Chrome 扩展的快捷键机制存在限制：通过 `manifest.json` 的 `commands` 定义的快捷键只能在 `chrome://extensions/shortcuts` 页面由用户手动修改，无法通过扩展 API 程序化配置。为提供更好的用户体验，需要实现混合方案：

1. **Chrome 原生命令**：保留全局快捷键（Alt+Shift+S/R/F/D），确保在浏览器任何页面都能触发
2. **自定义快捷键系统**：在应用页面（Popup、Editor、CodeGen）内实现可配置的快捷键

### 约束

- Chrome 原生命令快捷键无法通过 API 修改，只能引导用户跳转配置
- 自定义快捷键需要 content script 注入才能在页面内监听
- 快捷键冲突检测需要维护冲突列表

### 利益相关者

- 终端用户：希望自定义快捷键以匹配个人习惯
- 开发者：需要维护两套快捷键系统

---

## 目标 / 非目标

### 目标

- 在设置页面提供快捷键可视化配置界面
- 支持用户通过按键录制方式设置新快捷键
- 检测并阻止冲突快捷键设置
- 在 Popup/Editor/CodeGen 页面内支持自定义快捷键触发命令

### 非目标

- 修改 Chrome 原生命令快捷键（技术限制）
- 支持全局自定义快捷键（需要 content script 注入所有页面，性能开销大）
- 支持组合键序列（如 `Ctrl+K, Ctrl+S`）

---

## 决策

### 架构方案：混合快捷键系统

```
┌─────────────────────────────────────────────────────────────────┐
│                      快捷键触发流程                              │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│  用户按键                                                        │
│     │                                                            │
│     ▼                                                            │
│  ┌─────────────────┐                                             │
│  │ Chrome 原生命令  │ ──全局快捷键──▶ Background Service Worker   │
│  └─────────────────┘                                             │
│     │                                                            │
│     │ 非全局快捷键                                                │
│     ▼                                                            │
│  ┌─────────────────┐                                             │
│  │ Content Script  │ ──页面内快捷键──▶ 消息传递到对应页面         │
│  └─────────────────┘                                             │
│     │                                                            │
│     ▼                                                            │
│  ┌─────────────────┐                                             │
│  │ Popup/Editor/   │ ──执行对应命令                              │
│  │ CodeGen         │                                             │
│  └─────────────────┘                                             │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘
```

### 存储方案

```typescript
interface ShortcutConfig {
  // 原生命令快捷键（只读，展示用）
  native: {
    captureVisible: string;    // 'Alt+Shift+S'
    captureRegion: string;     // 'Alt+Shift+R'
    captureFullpage: string;   // 'Alt+Shift+F'
    captureDesktop: string;    // 'Alt+Shift+D'
  };
  // 自定义快捷键（可配置）
  custom: {
    captureVisible: string;    // 默认 'Alt+S'
    captureRegion: string;     // 默认 'Alt+R'
    captureFullpage: string;   // 默认 'Alt+F'
    captureDesktop: string;    // 默认 'Alt+D'
  };
  // 是否启用自定义快捷键
  enabled: boolean;
}
```

### 冲突检测列表

维护系统保留快捷键列表，在用户设置时检测：

```typescript
const SYSTEM_SHORTCUTS = [
  'Ctrl+T', 'Ctrl+W', 'Ctrl+Tab', 'Ctrl+Shift+Tab',
  'Ctrl+L', 'Ctrl+D', 'Ctrl+H', 'Ctrl+J', 'Ctrl+K',
  'F1', 'F5', 'F11', 'F12',
  'Alt+Left', 'Alt+Right', 'Alt+Up', 'Alt+Down',
  // ... 更多系统快捷键
];
```

### 考虑的替代方案

| 方案 | 优点 | 缺点 | 结论 |
|------|------|------|------|
| 仅 Chrome 原生命令 | 实现简单，全局可用 | 用户需跳转配置，体验差 | 不采用 |
| 仅自定义快捷键 | 完全可控 | 仅在特定页面生效，无全局快捷键 | 不采用 |
| **混合方案** | 兼顾全局和自定义 | 实现复杂度适中 | **采用** |

## 风险 / 权衡

| 风险 | 缓解措施 |
|------|----------|
| 快捷键冲突导致功能失效 | 完善冲突检测，阻止设置并提示替代方案 |
| 用户误改快捷键后无法恢复 | 提供「恢复默认」按钮 |
| Content Script 注入影响页面性能 | 仅在需要时激活监听，使用事件委托 |
| 两套快捷键系统混淆 | UI 清晰区分「全局快捷键」和「页面快捷键」 |

---

## 迁移计划

### 阶段 1：基础架构

1. 扩展类型定义，添加 `ShortcutConfig`
2. 更新 `settings-store`，支持快捷键配置存储
3. 创建快捷键录制组件 `ShortcutRecorder`

### 阶段 2：设置页面

1. 重构快捷键设置区块，区分全局/页面快捷键
2. 实现快捷键编辑功能
3. 实现冲突检测和提示

### 阶段 3：快捷键执行

1. 在 Popup 中监听自定义快捷键
2. 在 Editor 中监听自定义快捷键
3. 在 CodeGen 中监听自定义快捷键

### 回滚方案

- 删除新增代码
- 恢复原有快捷键展示组件
- 清理存储中的快捷键配置
