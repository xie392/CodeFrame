# 技术设计：Editor 裁剪功能

## 上下文

Editor 当前采用双层 Canvas 架构：
- 底层：`<img>` 元素显示原始图片
- 上层：Canvas 绘制所有标注（箭头、矩形、文字、马赛克）

裁剪功能需要修改图片源数据，这与现有标注系统的工作方式有本质区别。

## 目标 / 非目标

**目标：**
- 提供直观的裁剪框交互（拖拽创建、移动、调整大小）
- 裁剪后更新图片数据源
- 正确处理裁剪后标注坐标的映射

**非目标：**
- 撤销/重做功能（可作为后续迭代）
- 固定比例裁剪（如 16:9、4:3）
- 旋转裁剪框

## 决策

### 1. 裁剪工具模式

**决策：** 裁剪作为独立工具，而非永久性功能面板

**理由：**
- 与现有工具栏设计一致（箭头、矩形、马赛克等都是独立工具）
- 用户完成裁剪后自动切换回选择工具，符合编辑流程
- 避免界面复杂化

### 2. 裁剪框渲染方式

**决策：** 在标注 Canvas 上渲染裁剪框

**理由：**
- 复用现有 Canvas 渲染管线
- 裁剪框本质上是一种临时标注
- 无需引入新的 DOM 层

### 3. 裁剪后标注处理

**决策：** 裁剪后移除所有标注，重置为空白画布

**理由：**
- 标注坐标基于原图，裁剪后坐标系统改变
- 自动映射标注位置复杂且易出错
- 裁剪后标注可能超出新图片边界
- 用户可在裁剪后重新添加标注

**替代方案：** 自动映射标注坐标到新坐标系
- **否决理由：** 边界情况复杂（标注部分在裁剪区域外），用户体验不可预测

### 4. 裁剪确认方式

**决策：** 提供三种确认方式
1. 键盘 Enter 键
2. 双击裁剪区域
3. 点击工具栏"确认"按钮（在裁剪工具激活时显示）

**理由：**
- 多种方式满足不同用户习惯
- 与主流图片编辑软件一致

## 风险 / 权衡

| 风险 | 缓解措施 |
|------|----------|
| 大图片裁剪性能 | 使用 requestAnimationFrame 优化渲染 |
| 标注丢失导致用户不满 | 裁剪确认前显示警告提示 |
| 裁剪后图片尺寸变化导致布局闪烁 | 裁剪后自动重置缩放和平移 |

## 数据结构

```typescript
// 裁剪区域（图片坐标系）
interface CropArea {
  x: number;      // 左上角 X
  y: number;      // 左上角 Y
  width: number;  // 宽度
  height: number; // 高度
}

// 裁剪状态
interface CropState {
  isCropping: boolean;      // 是否处于裁剪模式
  cropArea: CropArea | null; // 当前裁剪框
  isDraggingCrop: boolean;   // 是否正在拖拽裁剪框
  cropDragType: 'move' | 'resize-tl' | 'resize-tr' | 'resize-bl' | 'resize-br' | 'resize-t' | 'resize-b' | 'resize-l' | 'resize-r' | null;
}
```

## 关键实现步骤

1. **激活裁剪工具**
   - 设置 `activeTool = 'crop'`
   - 初始化裁剪框为全图区域

2. **绘制裁剪框**
   - 绘制半透明遮罩层（暗化裁剪区域外）
   - 绘制裁剪框边框（虚线）
   - 绘制 8 个控制点

3. **交互处理**
   - 检测鼠标位置判断操作类型（移动/调整大小）
   - 实时更新裁剪区域

4. **确认裁剪**
   - 创建临时 Canvas 执行裁剪
   - 更新 `imageData` 状态
   - 清空所有标注
   - 重置视图（缩放=1，偏移=0）
