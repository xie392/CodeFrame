## 上下文

CodeFrame 项目即将在 GitHub 开源，需要确保安全性和合规性。安全审查发现两个依赖漏洞，且缺少部分开源标准文件。

### 约束
- 保持向后兼容
- 不影响现有功能
- 遵循 MIT 许可证要求

## 目标 / 非目标

**目标：**
- 修复已知依赖漏洞
- 补充开源必备文件
- 建立自动化安全检查

**非目标：**
- 重构现有代码
- 添加新功能
- 修改许可证类型

## 决策

### 1. 依赖更新策略
- **决策**：直接更新到最新稳定版本
- **原因**：漏洞影响开发环境，不影响生产构建，风险可控
- **替代方案**：锁定特定版本 → 不采用，无法获取后续安全修复

### 2. Dependabot 配置
- **决策**：启用 npm 依赖自动更新，每周检查
- **原因**：及时获取安全更新通知
- **配置范围**：仅监控生产依赖，开发依赖手动更新

### 3. CI 安全检查
- **决策**：在构建前添加 `pnpm audit` 步骤
- **原因**：阻止有漏洞的代码合并
- **严重级别**：仅阻止高危和严重漏洞

## 风险 / 权衡

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| 依赖更新引入破坏性变更 | 构建失败 | 运行完整测试套件验证 |
| Dependabot PR 过多 | 维护负担 | 配置自动合并低风险更新 |

## 迁移计划

1. 更新依赖 → 本地验证 → 提交
2. 添加新文件 → 无迁移需求
3. 更新 CI → 立即生效
