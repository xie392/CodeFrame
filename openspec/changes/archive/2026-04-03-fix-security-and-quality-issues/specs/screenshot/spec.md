## 新增需求

### 需求：图像数据处理安全

系统必须安全地处理 base64 编码的图像数据，防止无效数据导致扩展崩溃。

#### 场景：无效 base64 数据处理

- **当** `atob()` 接收到无效的 base64 编码数据
- **那么** 系统必须捕获异常并抛出明确的错误信息
- **且** 不得导致 Service Worker 崩溃

#### 场景：空 data URL 处理

- **当** data URL 不包含逗号分隔符或 base64 部分为空
- **那么** 系统必须抛出「无效的 data URL」错误
- **且** 不得尝试解码空字符串

---

### 需求：存储数据类型验证

系统必须验证从 `chrome.storage` 读取的数据类型，防止恶意或损坏的数据导致运行时错误。

#### 场景：语言设置类型验证

- **当** 从 `chrome.storage.local` 读取语言设置
- **那么** 系统必须验证值是否为有效的语言代码（'zh-CN' 或 'en-US'）
- **且** 若值无效或不存在，必须返回默认值 'zh-CN'

#### 场景：存储数据损坏处理

- **当** 存储中的设置数据结构异常或损坏
- **那么** 系统必须安全地回退到默认值
- **且** 不得抛出未捕获的异常

---

### 需求：生产环境日志控制

系统必须在生产环境中禁用调试日志，防止敏感信息泄露。

#### 场景：开发环境日志输出

- **当** 运行环境为开发模式（`import.meta.env.DEV === true`）
- **那么** 系统可以输出调试日志到控制台
- **且** 日志必须包含 `[CodeFrame]` 前缀

#### 场景：生产环境日志禁用

- **当** 运行环境为生产模式（`import.meta.env.DEV === false`）
- **那么** 系统必须禁止输出调试日志（`console.log`）
- **且** 错误日志（`console.error`）仍然允许输出

---

### 需求：图像资源内存管理

系统必须正确管理 `ImageBitmap` 资源的生命周期，防止内存泄漏。

#### 场景：正常流程资源释放

- **当** 图像处理操作成功完成
- **那么** 系统必须调用 `imageBitmap.close()` 释放资源
- **且** 必须在不再需要资源时立即释放

#### 场景：错误路径资源释放

- **当** 图像处理操作过程中发生错误
- **那么** 系统必须使用 `try-finally` 确保已创建的 `ImageBitmap` 被释放
- **且** 错误必须正确传播给调用者
