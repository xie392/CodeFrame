## 需求
### 需求：标签触发构建

当推送符合语义化版本格式的标签时，系统**必须**自动触发构建流水线。

#### 场景：推送有效标签触发构建

- **当** 推送格式为 `v*.*.*` 的标签（如 `v1.0.0`）
- **那么** 自动触发构建工作流
- **并且** 使用标签版本号作为发布版本

#### 场景：推送无效标签不触发构建

- **当** 推送格式不符合 `v*.*.*` 的标签
- **那么** 不触发构建工作流

---

### 需求：自动构建扩展

系统**必须**在触发后自动构建 Chrome 扩展。

#### 场景：成功构建扩展

- **当** 构建工作流被触发
- **那么** 检出代码
- **并且** 安装项目依赖（使用 pnpm）
- **并且** 执行 `pnpm build` 构建扩展
- **并且** 构建产物输出到 `dist` 目录

#### 场景：构建失败中止流程

- **当** 构建过程发生错误
- **那么** 中止工作流
- **并且** 不创建 Release

---

### 需求：自动打包压缩

构建成功后，系统**必须**将构建产物打包为 zip 格式。

#### 场景：成功打包扩展

- **当** 构建成功完成
- **那么** 将 `dist` 目录内容打包为 zip 文件
- **并且** 文件命名为 `codeframe-{version}.zip`
- **并且** 不包含源码映射文件（.map）

---

### 需求：自动发布 Release

系统**必须**在打包完成后自动创建 GitHub Release。

#### 场景：成功创建 Release

- **当** 打包成功完成
- **那么** 创建 GitHub Release
- **并且** 使用标签名作为 Release 标题
- **并且** 将 zip 文件附加为发布产物

#### 场景：Release 已存在

- **当** 对应版本的 Release 已存在
- **那么** 更新现有 Release 的产物

---

### 需求：Issue 模板

系统**必须**提供标准化的 Issue 模板，帮助用户有效报告问题或请求功能。

#### 场景：提交 Bug 报告

- **当** 用户选择 Bug Report 模板
- **那么** 显示结构化表单
- **并且** 表单包含：问题描述、复现步骤、期望行为、实际行为、环境信息

#### 场景：提交功能请求

- **当** 用户选择 Feature Request 模板
- **那么** 显示结构化表单
- **并且** 表单包含：功能描述、使用场景、期望解决方案

---

### 需求：PR 模板

系统**必须**提供标准化的 PR 模板，确保代码变更的可审查性。

#### 场景：创建 Pull Request

- **当** 用户创建新的 Pull Request
- **那么** 自动填充 PR 模板
- **并且** 模板包含：变更描述、变更类型、测试清单、截图对比（可选）

### 需求：依赖漏洞扫描

CI 流水线必须自动扫描依赖漏洞，阻止高危漏洞合并。

#### 场景：检测到高危漏洞时阻止构建

- **当** 依赖存在高危或严重漏洞
- **那么** CI 构建失败并显示漏洞详情

#### 场景：无漏洞时继续构建

- **当** 依赖无已知漏洞
- **那么** CI 继续执行后续步骤

---

### 需求：自动依赖更新

项目必须配置 Dependabot 自动检测依赖更新。

#### 场景：每周检查依赖更新

- **当** 每周一到达
- **那么** Dependabot 检查依赖更新并创建 PR

#### 场景：安全更新立即处理

- **当** 发现安全漏洞
- **那么** Dependabot 立即创建安全更新 PR

---

### 需求：贡献指南

项目必须提供贡献指南，说明如何参与项目开发。

#### 场景：新贡献者了解贡献流程

- **当** 开发者访问 CONTRIBUTING.md
- **那么** 能够了解开发环境搭建、代码规范、提交规范、PR 流程

---

### 需求：安全策略

项目必须提供安全策略，说明如何报告安全漏洞。

#### 场景：发现漏洞时知道如何报告

- **当** 安全研究员发现漏洞
- **那么** 能够通过 SECURITY.md 了解报告方式和响应时间
