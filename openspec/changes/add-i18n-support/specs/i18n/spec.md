## 新增需求

### 需求：国际化系统

系统**必须**提供完整的国际化（i18n）支持，允许用户在中文和英文界面语言之间切换。

#### 场景：初始化国际化系统

- **当** 应用启动时
- **那么** 系统读取用户语言设置（默认为 `zh-CN`）
- **且** 加载对应的语言包
- **且** 界面显示为对应语言的文字

#### 场景：切换界面语言

- **当** 用户在设置页面选择不同语言
- **那么** 语言设置保存到 `chrome.storage.local`
- **且** 系统自动切换语言包
- **且** 所有已打开的页面界面立即更新为新语言
- **且** 无需刷新页面或重启扩展

#### 场景：语言包加载失败

- **当** 指定语言的翻译文件加载失败
- **那么** 系统回退到默认语言（`zh-CN`）
- **且** 在控制台输出警告信息

#### 场景：翻译缺失

- **当** 某个翻译键在当前语言包中不存在
- **那么** 显示翻译键本身作为后备
- **且** 在控制台输出警告信息（仅开发模式）

---

### 需求：翻译文件组织

系统**必须**按模块组织翻译文件，便于维护和扩展。

#### 场景：翻译文件结构

- **当** 开发者添加新翻译时
- **那么** 按模块分类存储（`common`、`options`、`popup`、`editor`、`codegen`）
- **且** 每个模块有独立的 JSON 文件
- **且** 支持中英文双语

#### 场景：翻译键命名规范

- **当** 开发者定义翻译键时
- **那么** 使用点号分隔的命名空间（如 `options.section.general`）
- **且** 键名语义清晰，易于理解
- **且** 避免过度嵌套（最多 3 层）

---

### 需求：页面国际化

系统**必须**支持所有用户可见页面的国际化。

#### 场景：Options 页面国际化

- **当** 用户访问设置页面
- **那么** 所有文字（标题、标签、按钮、提示）显示为当前语言
- **且** 语言选择器显示可选语言列表（简体中文 / English）

#### 场景：Popup 页面国际化

- **当** 用户打开扩展弹窗
- **那么** 所有文字（功能名称、提示、错误信息）显示为当前语言

#### 场景：Editor 页面国际化

- **当** 用户使用图片编辑器
- **那么** 所有文字（工具名称、按钮、提示）显示为当前语言

#### 场景：CodeGen 页面国际化

- **当** 用户使用代码生成器
- **那么** 所有文字（标签、按钮、设置项）显示为当前语言

---

### 需求：Content Script 国际化

系统**必须**支持内容脚本的国际化。

#### 场景：遮罩层文字国际化

- **当** 用户进行区域选择截图
- **那么** 遮罩层的提示文字显示为当前语言

#### 场景：倒计时提示国际化

- **当** 用户使用延迟截图功能
- **那么** 倒计时界面的提示文字显示为当前语言

---

### 需求：语言切换持久化

系统**必须**持久化语言设置，确保浏览器重启后保留用户选择。

#### 场景：保存语言设置

- **当** 用户切换语言
- **那么** 语言设置立即保存到 `chrome.storage.local`
- **且** 下次打开扩展时使用已保存的语言

#### 场景：首次使用

- **当** 用户首次安装扩展
- **那么** 使用默认语言（`zh-CN`）
- **且** 用户可随时切换语言
