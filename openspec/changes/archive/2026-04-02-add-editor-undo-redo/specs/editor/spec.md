## 新增需求

### 需求：Editor 撤销功能

Editor 必须提供撤销功能，允许用户撤销最近的操作，恢复到上一个历史状态。

#### 场景：工具栏撤销按钮

- **当** 用户查看左侧工具栏
- **那么** 必须显示撤销按钮（Undo2 图标）
- **且** 当存在可撤销的历史记录时，按钮必须可点击
- **且** 当不存在可撤销的历史记录时，按钮必须禁用且显示半透明

#### 场景：点击撤销按钮

- **当** 用户点击撤销按钮
- **那么** Editor 必须恢复到上一个历史状态
- **且** 当前状态必须被保存到未来状态栈
- **且** 所有标注和视图必须更新为历史状态

#### 场景：键盘快捷键撤销

- **当** 用户按下 `Ctrl+Z`（Windows）或 `Cmd+Z`（macOS）
- **那么** 必须执行撤销操作
- **且** 如果焦点在输入框中，禁止触发撤销

#### 场景：撤销创建标注

- **当** 用户创建箭头、矩形、文字或马赛克标注后执行撤销
- **那么** 新创建的标注必须被移除
- **且** 选择状态必须清除

#### 场景：撤销修改标注

- **当** 用户修改标注的位置、尺寸或样式后执行撤销
- **那么** 标注必须恢复到修改前的状态

#### 场景：撤销删除标注

- **当** 用户删除标注后执行撤销
- **那么** 被删除的标注必须恢复到画布上
- **且** 标注的所有属性必须保持删除前的状态

#### 场景：撤销裁剪操作

- **当** 用户执行裁剪操作后执行撤销
- **那么** 图片必须恢复到裁剪前的原始图片
- **且** 所有标注必须恢复到裁剪前的状态
- **且** 视图状态必须恢复

### 需求：Editor 恢复功能

Editor 必须提供恢复功能，允许用户恢复已被撤销的操作。

#### 场景：工具栏重做按钮

- **当** 用户查看左侧工具栏
- **那么** 必须显示重做按钮（Redo2 图标），位于撤销按钮之后
- **且** 当存在可恢复的未来状态时，按钮必须可点击
- **且** 当不存在可恢复的未来状态时，按钮必须禁用且显示半透明

#### 场景：点击重做按钮

- **当** 用户点击重做按钮
- **那么** Editor 必须恢复到下一个未来状态
- **且** 当前状态必须被保存到历史记录栈
- **且** 所有标注和视图必须更新为未来状态

#### 场景：键盘快捷键重做

- **当** 用户按下 `Ctrl+Shift+Z`（Windows）或 `Cmd+Shift+Z`（macOS）
- **那么** 必须执行重做操作
- **且** 如果焦点在输入框中，禁止触发重做
- **当** 用户按下 `Ctrl+Y`（Windows）或 `Cmd+Y`（macOS）
- **那么** 必须执行重做操作（兼容快捷键）

#### 场景：新操作清除未来状态

- **当** 用户在撤销后执行新的操作
- **那么** 所有未来状态必须被清除
- **且** 新操作必须被记录到历史记录栈

### 需求：Editor 历史记录管理

Editor 必须管理历史记录栈，确保撤销/恢复功能正确工作。

#### 场景：历史记录上限

- **当** 历史记录数量超过 50 条
- **那么** 最早的历史记录必须被丢弃
- **且** 保持最近 50 条历史记录

#### 场景：状态快照内容

- **当** 创建历史记录快照
- **那么** 必须包含所有标注数据（箭头、矩形、文字、马赛克）
- **且** 必须包含图片数据（imageData）
- **且** 必须包含视图状态（scale、offset）

#### 场景：连续快速操作

- **当** 用户连续快速执行多个操作
- **那么** 每个操作必须独立记录到历史记录栈
- **且** 撤销时必须逐个恢复
